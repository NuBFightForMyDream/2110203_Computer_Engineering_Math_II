01 Our arms will be full of vaccines

โจทย์

Six vaccine providers with price per dose c_i ≥ 0 and fatality prevention rate 0 ≤ p_i ≤ 1. Rate is obtained after two doses, except JaesoJose (single shot). For vaccine v_i the government must buy at least m_i doses to make the contract, and at most n_i doses can be delivered. The average prevention rate must be no less than R. There are X people. Minimize the cost.

No mix-and-match · no boosters · fractional vaccines OK · no contract with BiZerTech (v₂) and Oderman (v₃), but order all other four · average rate is the weighted average (e.g. 10 Vinosac + 5 ZenaCasatra → (10p₁ + 5p₅)/15) · unvaccinated person has rate p₀; not everyone needs to be vaccinated.

สรุป: ซื้อวัคซีน 4 ยี่ห้อ v₁, v₄, v₅, v₆ ให้ค่าป้องกันเฉลี่ย ≥ R โดยจ่ายน้อยที่สุด

จุดที่คนพลาด: (1) วัคซีนส่วนใหญ่ใช้ 2 โดส/คน แต่ JaesoJose ใช้ 1 · (2) ต้องซื้อ "อย่างน้อย m_i" ซึ่งอาจมากกว่าที่ใช้จริง → แยก "โดสที่ซื้อ" กับ "คนที่ฉีด" เป็นคนละตัวแปร · (3) ค่าเฉลี่ยเป็นเศษส่วน → คูณตัวส่วนข้าม

รูปด้านบนใช้ ตัวเลขสมมติ (โจทย์ให้แต่สัญลักษณ์) เพื่อให้เห็นว่าโมเดลเลือกอะไร ลองเลื่อน R ดูได้

0.60

  1. ตัดสิ่งที่ไม่เกี่ยวออกก่อน

    • v₂, v₃ ไม่ทำสัญญา → ไม่มีตัวแปรของมัน (หรือเท่ากับ 0)
    • "ไม่ mix-and-match, ไม่มี booster" → คนหนึ่งคนได้วัคซีน ยี่ห้อเดียว จำนวนโดสตายตัว (2 หรือ 1)
    • "ส่งของทันที", "ไม่สนผลข้างเคียง" → ไม่มีเรื่องเวลา ไม่ต้องมีตัวแปรตามเดือน
    • "เศษส่วนได้" → เป็น LP (ไม่ต้องเป็น integer)

    เหลือชุดวัคซีน I = {1, 4, 5, 6} และจำนวนโดสต่อคน k₁ = k₄ = k₅ = 2, k₆ = 1

  2. ตัวแปร: แยก "ซื้อ" กับ "ฉีด"

    y_i = จำนวนโดสวัคซีน i ที่ซื้อ  (i ∈ I)z_i = จำนวนคนที่ได้รับวัคซีน i ครบ  (i ∈ I)

    ทำไมไม่ใช้ตัวแปรเดียว: ถ้าบังคับซื้อขั้นต่ำ m_i มากกว่าที่จะใช้ เราก็ยังต้องจ่ายค่าโดสที่เหลือ — ใช้สองตัวแปรถูกต้องกว่า (และถ้าใช้ตัวเดียวแล้วเขียน assumption ว่า "ใช้ทุกโดสที่ซื้อ" ก็พอรับได้)

  3. Objective: จ่ายค่าโดสที่ซื้อ

    min  c₁y₁ + c₄y₄ + c₅y₅ + c₆y₆

  4. โดสที่ใช้ ≤ โดสที่ซื้อ

    2z₁ ≤ y₁,  2z₄ ≤ y₄,  2z₅ ≤ y₅z₆ ≤ y₆ (JaesoJose เข็มเดียว)

    ในรูป: แท่งเข้ม = โดสที่ใช้ (k_i·z_i) ต้องไม่ยาวเกินแท่งอ่อน = โดสที่ซื้อ

  5. เงื่อนไขสัญญา: ขั้นต่ำ m_i และสูงสุด n_i

    "ตัดสินใจสั่งทั้ง 4 ยี่ห้อ" → ต้องถึงขั้นต่ำของทุกยี่ห้อ

    m_i ≤ y_i ≤ n_i  ∀ i ∈ {1, 4, 5, 6}

    ในรูป: เส้นประซ้าย = m_i, เส้นประขวา = n_i

  6. จำนวนคน

    z₁ + z₄ + z₅ + z₆ ≤ X

    ไม่ต้องฉีดทุกคน (โจทย์บอก) จึงเป็น ≤ ไม่ใช่ =

  7. ค่าป้องกันเฉลี่ย ≥ R → ทำให้เป็น linear

    คนที่ไม่ได้ฉีดมีค่า p₀ จำนวน X − Σz_i คน · เฉลี่ยทั้งประเทศ:

    [ p₁z₁ + p₄z₄ + p₅z₅ + p₆z₆ + p₀(X − Σz_i) ] / X ≥ R ⇔  (p₁ − p₀)z₁ + (p₄ − p₀)z₄ + (p₅ − p₀)z₅ + (p₆ − p₀)z₆ ≥ (R − p₀)X

    ตัวส่วน X เป็นค่าคงที่ คูณข้ามได้เลย → linear ✓

    ถ้าตีความว่าเฉลี่ยเฉพาะคนที่ฉีด (ตามตัวอย่าง 10 + 5 คนในโจทย์): Σp_iz_i ≥ R·Σz_i ⇔ Σ(p_i − R)z_i ≥ 0 — ก็ linear เหมือนกัน เลือกแบบหนึ่งแล้ว เขียน assumption

  8. Assumption ที่ควรเขียนกำกับ

    • ค่าเฉลี่ยคิดทั้งประชากร X (คนไม่ฉีดนับเป็น p₀)
    • โดสที่ซื้อเกินแล้วไม่ได้ใช้ ก็ต้องจ่าย (ทิ้งได้)
    • งบ "มีจำกัด" แต่โจทย์ไม่ให้ตัวเลข → ถ้ามีงบ B ให้เพิ่ม Σc_iy_i ≤ B (ถ้า infeasible แปลว่างบไม่พอ)

  9. Standard form

    min c₁y₁ + c₄y₄ + c₅y₅ + c₆y₆ s.t. y_i − e_i = m_i  ∀ i ∈ I (ขั้นต่ำ, e = surplus)   y_i + s_i = n_i  ∀ i ∈ I (สูงสุด, s = slack)   2z_i − y_i + w_i = 0  i = 1, 4, 5   z₆ − y₆ + w₆ = 0   z₁ + z₄ + z₅ + z₆ + s_X = X   Σi∈I (p_i − p₀) z_i − e_R = (R − p₀) X   ทุกตัวแปร ≥ 0

    RHS (R − p₀)X ถ้า R < p₀ จะติดลบ → คูณ −1 ทั้งแถว (แต่ปกติ R > p₀ ไม่งั้นไม่ต้องฉีดเลย)

  10. (แถม) ดูโมเดลทำงานด้วยตัวเลขสมมติ

    ตัวเลขในรูป: X = 1000, p₀ = 0.2 · Vinosac (p 0.5, ฿10) · Phisonarm (0.95, ฿30) · ZenaCasatra (0.75, ฿15) · JaesoJose (0.65, ฿20, 1 เข็ม)

    สังเกต: R ต่ำ → ซื้อแค่ขั้นต่ำ · R สูงขึ้น → เลือกยี่ห้อที่ "ได้ค่าป้องกันต่อบาท" ดีที่สุดก่อน (JaesoJose เข็มเดียวคุ้มเพราะ 1 คนใช้ 1 โดส) · R สูงเกินไป → infeasible

02 Hamtaro factory part 2 V2 — จ้างคนงาน 3 เดือน

โจทย์

Initially 50 hamster workers. 10% of the workers resign every month. A newly hired hamster must train for one month to become skilled, and 40% drop out before training finishes. Salary 8,000 THB/month per worker, training 500 THB per hamster. He may use fewer workers than required and pay a fine of 10,000 THB/person short.

Month123
Workers required5010070

The optimal solution does not have to be an integer. Formulate an LP and write the standard form; specify decision variables and assumptions.

โจทย์หลายช่วงเวลา (multi-period): เขียน "สมการสมดุล" (balance equation) ว่าคนงานเดือนหน้า = เหลือจากเดือนนี้ + คนที่เทรนจบ แล้วทุกอย่างจะเป็น linear เอง

รูปด้านบนคือไทม์ไลน์ของคนงาน — ทุกตัวเลขมาจากการแก้ LP จริง ลองเลื่อนค่าปรับดูว่าแผนเปลี่ยนเมื่อไหร่

10,000

  1. วาดไทม์ไลน์ก่อน (สำคัญที่สุดของข้อนี้)

    ทุกต้นเดือน t: มีคนงานฝีมือ w_t คน ทำงานเดือนนั้น · จ้างใหม่ h_t ตัวมาเทรน

    สิ้นเดือน t: คนงานลาออก 10% → เหลือ 0.9w_t · คนที่เทรนอยู่หลุด 40% → เหลือ 0.6h_t กลายเป็นคนงานฝีมือของเดือน t+1

    w_{t+1} = 0.9 w_t + 0.6 h_t

  2. Assumption (ต้องเขียน เพราะโจทย์ไม่บอก)

    • 50 คนเริ่มต้นเป็นคนงานฝีมือที่ทำงานเดือน 1 ได้เลย → w₁ = 50
    • ลาออก 10% เกิดตอน สิ้นเดือน (ทำงานครบเดือนแล้วค่อยออก, ได้เงินเดือนเต็ม)
    • คนที่กำลังเทรน ยังไม่นับ เป็นคนงาน และ ไม่ได้เงินเดือน — จ่ายแค่ค่าเทรน 500 ทุกตัวที่จ้าง (รวมตัวที่หลุดด้วย)
    • ไล่ออกไม่ได้ และจ้างในเดือน 3 ไม่มีประโยชน์ (เทรนจบหลังเดือน 3) → ไม่ต้องมี h₃

  3. ตัวแปรตัดสินใจ

    h₁, h₂ = จำนวนที่จ้างใหม่ต้นเดือน 1, 2 w₂, w₃ = คนงานฝีมือในเดือน 2, 3 (ตัวแปรช่วย) u₁, u₂, u₃ = จำนวนคนที่ขาด (โดนปรับ) ในแต่ละเดือน

  4. สมการสมดุล + จำนวนที่ขาด

    w₂ = 0.9(50) + 0.6h₁ = 45 + 0.6h₁ w₃ = 0.9w₂ + 0.6h₂ 50 + u₁ ≥ 50,  w₂ + u₂ ≥ 100,  w₃ + u₃ ≥ 70

    ความหมาย: คนที่มีจริง + คนที่ขาด ต้องครบที่ต้องการ (ถ้ามีเกิน u = 0 ก็ได้)

    กับดัก: อย่าเขียน u_t = req_t − w_t เพราะถ้า w_t มากกว่า req จะได้ u ติดลบ (เหมือนได้เงินคืน) — ใช้ ≥ กับ u_t ≥ 0 แล้ว min จะดัน u ลงเอง

  5. Objective: เงินเดือน + ค่าเทรน + ค่าปรับ

    min  8000(50 + w₂ + w₃) + 500(h₁ + h₂) + 10000(u₁ + u₂ + u₃)

    8000 × 50 ของเดือน 1 เป็นค่าคงที่ จะตัดออกจาก objective ก็ได้ (คำตอบไม่เปลี่ยน)

  6. Standard form

    min 8000w₂ + 8000w₃ + 500h₁ + 500h₂ + 10000u₁ + 10000u₂ + 10000u₃ (+ 400000) s.t. w₂ − 0.6h₁ = 45   −0.9w₂ + w₃ − 0.6h₂ = 0   u₁ − e₁ = 0   w₂ + u₂ − e₂ = 100   w₃ + u₃ − e₃ = 70   w₂, w₃, h₁, h₂, u₁, u₂, u₃, e₁, e₂, e₃ ≥ 0

  7. (แถม) คำตอบ — ทำไมยอมโดนปรับในเดือน 2?

    แก้ได้: h₁ = 54.63, h₂ = 0, w₂ = 77.78, w₃ = 70, u₂ = 22.22 · ต้นทุนรวม 1,831,759 บาท

    ทำไมไม่จ้างให้ครบ 100 ในเดือน 2? เพราะคนงานที่เพิ่มในเดือน 2 จะ เหลือ 90% ไปเดือน 3 ซึ่งต้องการแค่ 70 → กลายเป็นคนเกินที่ต้องจ่ายเงินเดือนแต่ไล่ออกไม่ได้

    ต้นทุนเพิ่ม 1 คนในเดือน 2 = 500/0.6 + 8000 + 0.9 × 8000 ≈ 16,033 บาท ค่าปรับ 1 คน = 10,000 บาท  <  16,033 → ยอมจ่ายค่าปรับดีกว่า

    จุดพอดี: w₂ = 70/0.9 = 77.78 → เดือน 3 ได้ 70 พอดี ไม่ต้องจ้างเพิ่ม (h₂ = 0) · ลองเลื่อนค่าปรับให้เกิน 16,033 ดู — LP จะเปลี่ยนไปจ้างให้ครบ 100

He can choose only one strategy. Needs to create 1000 items; at least 100 weekend hours for machine maintenance; fractional hours allowed; no other limit on hours. What strategy minimizes salary cost, and how should hours be distributed? Provide a method using LP and the standard form.

"เลือกได้แค่ 1 จาก 3" เป็นการตัดสินใจแบบไม่ต่อเนื่อง LP ตัวเดียวทำไม่ได้ตรง ๆ → วิธีที่ง่ายและถูกต้อง: แก้ LP 3 ตัว (หนึ่งตัวต่อหนึ่ง strategy) แล้วเลือกตัวที่ต้นทุนต่ำสุด

  1. ตัวแปร

    d = จำนวนชั่วโมงทำงานวันธรรมดา (weekday) รวมe = จำนวนชั่วโมงทำงานวันหยุด (weekend) รวม

    ไม่ต้องแยกเป็นรายคน — โจทย์บอกว่า "shift ชั่วโมงของทุกคนได้" และ "ไม่มีข้อจำกัดชั่วโมงรวม"

  2. ข้อจำกัด (เหมือนกันทุก strategy)

    1·d + 0.7·e ≥ 1000 (ผลิตให้ได้ 1000 ชิ้น) e ≥ 100 (ดูแลเครื่องจักรวันหยุด) d, e ≥ 0

    ในรูป: region สีเขียว = ทุกคู่ (d, e) ที่ทำได้

  3. Objective ของ strategy k

    LP_k:  min  a_k·d + b_k·eA: 10d + 40e   B: 15d + 20e   C: 20d + 15e

  4. แก้ LP_A

    คิดแบบ "ราคาต่อชิ้น": weekday 10/1 = 10 บาท/ชิ้น · weekend 40/0.7 ≈ 57.1 บาท/ชิ้น → ใช้ weekend น้อยที่สุด (100 ชม.) ที่เหลือใช้ weekday

    e = 100 → ได้ 70 ชิ้น  ⇒  d = 1000 − 70 = 930cost_A = 10(930) + 40(100) = 13,300

  5. แก้ LP_B

    weekday 15 บาท/ชิ้น · weekend 20/0.7 ≈ 28.6 บาท/ชิ้น → weekday ยังถูกกว่า → e = 100, d = 930

    cost_B = 15(930) + 20(100) = 15,950

  6. แก้ LP_C — จุดหลอก

    ค่าแรง weekend (15) ถูกกว่า weekday (20) ต่อชั่วโมง แต่ ต่อชิ้น: weekend 15/0.7 ≈ 21.4 > weekday 20 → weekday ยังคุ้มกว่า!

    e = 100, d = 930  ⇒  cost_C = 20(930) + 15(100) = 20,100

    กับดัก: เทียบราคา "ต่อชั่วโมง" ไม่ได้ ต้องเทียบ "ต่อชิ้น" เพราะ productivity ไม่เท่ากัน — ในรูปคือความชันของ isocost เทียบกับเส้น 1000 ชิ้น

  7. เทียบแล้วเลือก

    Strategy(d, e)cost
    A(930, 100)13,300
    B(930, 100)15,950
    C(930, 100)20,100
    คำตอบ เลือก Strategy A · weekday 930 ชม. · weekend 100 ชม. · ค่าแรง 13,300

  8. Standard form (เขียน 1 ชุด ใช้ได้ทั้ง 3 strategy)

    สำหรับ k ∈ {A, B, C}:  min a_k d + b_k e s.t. d + 0.7e − s₁ = 1000   e − s₂ = 100   d, e, s₁, s₂ ≥ 0 (a_A, b_A) = (10, 40), (a_B, b_B) = (15, 20), (a_C, b_C) = (20, 15)

    อีกวิธี (ถ้าเรียน integer programming แล้ว): แยกชั่วโมงตาม strategy d_k, e_k + ตัวแปร 0/1 y_k, Σy_k = 1, d_k + e_k ≤ M·y_k — แต่โจทย์ขอ "LP" จึงใช้วิธีแก้ 3 ตัวก็ครบ
