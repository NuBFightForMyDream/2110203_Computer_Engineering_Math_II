Q6 Election madness 5 pts

โจทย์

Parliament of 400 seats, one per constituency, no party list. Majority = 201. Hamtaro wants as many seats as possible. 100 constituencies are certain wins. Others:

Voting trendNo. of constituenciesCampaigns neededAdvanced campaigns needed
Very close3010
Trailing a bit5030
Trailing considerably7071
Almost no chance50163
Impossible to flip100N/AN/A

Campaign = 1M SFD, advanced campaign = 5M SFD. "Buying a cobra" costs 70M SFD and flips any constituency (including impossible ones) without campaigns; at most 5 cobras. Budget 1 billion SFD. What is the maximum number of seats? Formulate as a linear/integer program.

ไอเดีย: ทุกเขตมีค่าเท่ากัน (1 ที่นั่ง) แต่ "ราคา" ต่างกัน → แปลงทุกอย่างเป็น ราคาต่อ 1 เขต ก่อน แล้วจะเห็นว่าควรซื้อเขตถูกสุดก่อน

1000

  1. นับเขตก่อน

    100 + 30 + 50 + 70 + 50 + 100 = 400 ครบทุกเขต · ชนะแน่ 100 เขต · ที่เหลือ 300 เขตต้อง "ซื้อ" ด้วยการหาเสียงหรือซื้องูเห่า

    ในรูป: แถบที่นั่ง 400 ช่อง — สีเทา = ชนะแน่, เส้นแดง = majority 201

  2. ราคาต่อ 1 เขต (ต้องใช้ทั้ง campaign และ advanced ตามตาราง)

    ประเภทคำนวณล้าน SFD / เขตจำนวน
    Very close1·1 + 0·5130
    Trailing a bit3·1 + 0·5350
    Trailing considerably7·1 + 1·51270
    Almost no chance16·1 + 3·53150
    ซื้องูเห่า (เขตไหนก็ได้)—70≤ 5

    Assumption: การ flip เขตหนึ่งต้องจ่ายทั้ง campaign และ advanced campaign ตามจำนวนในตาราง · งบ 1 billion = 1000 ล้าน

  3. ตัวแปรตัดสินใจ (จำนวนเต็ม)

    x_k = จำนวนเขตประเภท k ที่ flip ด้วยการหาเสียง  k = 1…4 y_k = จำนวนเขตประเภท k ที่ flip ด้วยงูเห่า  k = 1…5 (k = 5 คือ impossible) x_k, y_k ∈ ℤ, ≥ 0

    ต้องเป็นจำนวนเต็ม เพราะ flip ครึ่งเขตไม่ได้ — นี่คือ integer program (โจทย์บอก "linear/integer program")

  4. Objective: ที่นั่งมากที่สุด

    max  100 + x₁ + x₂ + x₃ + x₄ + y₁ + y₂ + y₃ + y₄ + y₅

  5. ข้อจำกัด

    1x₁ + 3x₂ + 12x₃ + 31x₄ + 70(y₁ + y₂ + y₃ + y₄ + y₅) ≤ 1000 (งบ) x₁ + y₁ ≤ 30,  x₂ + y₂ ≤ 50,  x₃ + y₃ ≤ 70,  x₄ + y₄ ≤ 50,  y₅ ≤ 100 (เขตมีจำกัด) y₁ + y₂ + y₃ + y₄ + y₅ ≤ 5 (งูเห่าไม่เกิน 5)

    ตัวแปรเดียวกันห้ามนับซ้ำ: เขตหนึ่ง flip ด้วยวิธีเดียว จึงรวม x_k + y_k ไม่เกินจำนวนเขต

  6. เขียนรวมเป็น IP (คำตอบที่ต้องส่ง)

    max 100 + Σk=1..4 x_k + Σk=1..5 y_k s.t. x₁ + 3x₂ + 12x₃ + 31x₄ + 70Σk y_k ≤ 1000   x_k + y_k ≤ N_k  (N = 30, 50, 70, 50) · y₅ ≤ 100   Σk y_k ≤ 5   x_k, y_k ∈ ℤ≥0

  7. แก้: ซื้อเขตที่ถูกที่สุดก่อน

    ทุกเขตให้ 1 ที่นั่งเท่ากัน → อยากได้จำนวนมากสุดภายใต้งบ = เลือกของถูกก่อนเสมอ (สลับเขตแพงออกแล้วใส่เขตถูกกว่าเข้าไปไม่มีทางแย่ลง)

    Very close 30 เขต × 1 = 30  → เหลือ 970 Trailing a bit 50 เขต × 3 = 150  → เหลือ 820 Trailing considerably: ⌊820 / 12⌋ = 68 เขต × 12 = 816  → เหลือ 4 เหลือ 4 ล้าน ซื้ออะไรไม่ได้อีก (ถูกสุดที่เหลือคือ 12)

  8. คำตอบ + ตรวจ

    คำตอบ 100 + 30 + 50 + 68 = 248 ที่นั่ง (x = (30, 50, 68, 0), ไม่ซื้องูเห่า) · ใช้งบ 996 ล้าน · เกิน majority 201 ✓
    • ทำไมไม่ซื้องูเห่า: 70 ล้าน/เขต แพงกว่าทุกแบบที่ยังเหลือ (12 หรือ 31) — ไม่ผิดกฎหมายด้วย 😅
    • ถ้าคลาย integer (LP relaxation): ได้ x₃ = 68.33 → 248.33 ที่นั่ง ซึ่งเป็นไปไม่ได้จริง ปัดลงเป็น 248 พอดีในข้อนี้ (แต่โดยทั่วไป ปัดเศษ LP ไม่รับประกันว่า optimal)

  9. (แถม) ถ้างบเปลี่ยน?

    เลื่อน slider: งบเกิน 30 + 150 + 840 + 1550 = 2570 ล้าน ถึงจะเริ่มซื้องูเห่า (ตอนนั้นซื้อเขตอื่นหมดแล้ว) และได้สูงสุด 300 + 5 = 305 ที่นั่งที่ 2920 ล้าน

    ต้องใช้งบเท่าไหร่ถึงชนะเกินครึ่ง (201)? ต้อง flip 101 เขต: 30 + 50 + 21 เขต → 30 + 150 + 21·12 = 432 ล้าน

Q7 Hamtaro first crisis (2025) — จัดชั้นวางหน้าร้าน 4 pts + bonus 3

โจทย์

Front shelf has P levels, each of width W, height H, depth D. N products; product i has quantity n_i, dimensions w_i, h_i, d_i and attractiveness A_ij when placed on level j. Assumptions: (1) orientation cannot be changed · (2) multiple copies of the same item allowed without penalty · (3) only one row of items per level (no items behind) · (4) no stacking.

7.1 maximize attractiveness: which item, which level, how many? Formulate a mathematical program. · 7.2 orientation may change but rotating halves attractiveness · 7.3 also allow multiple rows per level, but item and orientation must be the same · 7.4 (bonus) also allow stacking.

ไอเดีย: ภายใต้ assumption 3, 4 ของบนชั้นหนึ่งเรียงเป็น แถวเดียวจากซ้ายไปขวา → ทรัพยากรที่ใช้หมดคือ ความกว้าง อย่างเดียว ส่วนความสูง/ความลึกแค่ต้อง "ใส่ได้" → เป็น knapsack หลายใบ (multiple knapsack)

รูปด้านบนเป็นตัวอย่างสมมติ: ชั้น 2 ระดับ W = 100, H = 30, D = 40 และสินค้า 4 แบบ — คำตอบในรูปแก้ด้วย integer programming จริง

  1. อะไรคงที่ อะไรเลือกได้

    คงที่: P, W, H, D, n_i, w_i, h_i, d_i, A_ij · เลือกได้: วางสินค้า i บนชั้น j กี่ชิ้น

    ตารางตัวอย่างในรูป (ตัวเลขสมมติ):

    สินค้าw × h × dn_iA_i1 / A_i2
    Dog food30 × 28 × 1549 / 6
    Cat toys20 × 12 × 10105 / 4
    Hamster wheel25 × 25 × 2528 / 3
    Cat tree (สูง!)15 × 40 × 12210 / 10

  2. ตัวแปร

    x_ij ∈ ℤ≥0 = จำนวนชิ้นของสินค้า i ที่วางบนชั้น j  (i = 1…N, j = 1…P)

    ต้องเป็นจำนวนเต็ม (วางครึ่งชิ้นไม่ได้) → integer program · assumption 2 ทำให้ชิ้นซ้ำกันนับความน่าสนใจได้เต็ม ๆ ทุกชิ้น

  3. Objective

    max  Σi Σj A_ij x_ij

  4. ข้อจำกัดความกว้าง (หัวใจของข้อ)

    แถวเดียว ไม่ซ้อน → ของบนชั้น j เรียงต่อกัน ความกว้างรวมไม่เกิน W

    Σi w_i x_ij ≤ W  ∀ j = 1…P

  5. ข้อจำกัดจำนวน + ต้องใส่ได้

    Σj x_ij ≤ n_i  ∀ i (ของมีจำกัด) x_ij = 0  ถ้า h_i > H หรือ d_i > D (สูง/ลึกเกินชั้น วางไม่ได้)

    ในตัวอย่าง: Cat tree สูง 40 > H = 30 → วางไม่ได้เลย (ใน 7.1)

  6. 7.1 คำตอบ (formulation ครบ)

    max Σi,j A_ij x_ij s.t. Σi w_i x_ij ≤ W  ∀ j   Σj x_ij ≤ n_i  ∀ i   x_ij = 0  ∀ (i, j) ที่ h_i > H หรือ d_i > D   x_ij ∈ ℤ≥0

    ตัวอย่างในรูปได้ความน่าสนใจ 50 — สังเกตว่าของที่ "ชั้นบนน่าสนใจกว่ามาก" (wheel 8 vs 3) ถูกยกไปชั้น 1

  7. 7.2 หมุนได้ แต่ความน่าสนใจหารสอง

    กล่องหนึ่งวางได้ 6 ทิศ (สลับว่ามิติไหนเป็น กว้าง/สูง/ลึก) → ให้ o ∈ {1…6} แทนทิศ และ (w_io, h_io, d_io) เป็นขนาดในทิศนั้น (o = 1 คือทิศเดิม)

    ตัวแปร x_ijo ∈ ℤ≥0 max Σi,j A_ij x_ij1 + Σi,j Σo≥2 ½A_ij x_ijo s.t. Σi,o w_io x_ijo ≤ W  ∀ j   Σj,o x_ijo ≤ n_i  ∀ i   x_ijo = 0  ถ้า h_io > H หรือ d_io > D

    ในรูป: Cat tree นอนลง (กว้าง 12 ลึก 40) วางได้แล้ว · Dog food บางชิ้นถูกหมุนให้ "แคบ" ลง (15 แทน 30) เพื่อเบียดที่ → ได้ 55.5 (ชิ้นที่หมุนมีเส้นประ ↻)

  8. 7.3 หลายแถว (วางซ้อนไปด้านหลัง) — แต่ต้องเป็นของเดียวกัน ทิศเดียวกัน

    มองเป็น "คอลัมน์" จากหน้าไปหลัง: คอลัมน์ของสินค้า i ทิศ o กว้าง w_io และจุได้ k_io = ⌊D / d_io⌋ ชิ้น

    y_ijo ∈ ℤ≥0 = จำนวนคอลัมน์  x_ijo ∈ ℤ≥0 = จำนวนชิ้น x_ijo ≤ k_io · y_ijo (ชิ้นไม่เกินที่คอลัมน์จุได้) Σi,o w_io y_ijo ≤ W  ∀ j (ความกว้างนับตามคอลัมน์) Σj,o x_ijo ≤ n_i,  objective เหมือน 7.2

    ในรูป: ตัวเลข ×k บนกล่อง = ชิ้นที่อยู่เรียงไปข้างหลัง → ได้ 100

    ถ้าตีความว่าลูกค้าเห็นแค่แถวหน้า ความน่าสนใจควรคิดต่อคอลัมน์ (ใช้ y แทน x ใน objective) — เขียน assumption ที่เลือกไว้

  9. 7.4 (bonus) ซ้อนขึ้นด้านบนได้ด้วย

    ถ้ายังบังคับให้แต่ละคอลัมน์เป็นของชนิดเดียว ทิศเดียว: คอลัมน์กลายเป็น "บล็อก" ที่จุได้

    k_io = ⌊H / h_io⌋ · ⌊D / d_io⌋

    formulation เหมือน 7.3 ทุกอย่าง เปลี่ยนแค่ k_io → ตัวอย่างได้ 104 (Cat toys ซ้อน 2 ชั้น × ลึก 4 = 8 ต่อคอลัมน์)

    ถ้ายอมให้ของ ต่างชนิดกัน ซ้อนกันได้ จะกลายเป็น 3D bin packing ซึ่งต้องมีตัวแปรตำแหน่ง (x, y, z) ของแต่ละชิ้น + ข้อจำกัดไม่ทับกัน (ใช้ binary + big-M) — ยากกว่ามาก การอธิบายว่าทำไมยากก็ได้คะแนนส่วนหนึ่ง
